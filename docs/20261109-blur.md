> **구현 조사 정정 및 현재 상태**
>
> 아래 글의 GTK CSS `backdrop-filter` 예시는 적용하지 않습니다. GTK 4.24의 [공식 CSS 속성 목록](https://docs.gtk.org/gtk4/css-properties.html)에 이 속성은 없으므로, 예시대로 CSS를 추가하는 것만으로 컴포지터 블러를 요청할 수 없습니다. 아래의 해당 코드는 초기 아이디어로만 참고하세요.
>
> GTK 4.24는 `ext-background-effect-v1` 자체는 지원합니다. [GTK 4.24.1 Wayland 구현](https://github.com/GNOME/gtk/blob/4.24.1/gdk/wayland/gdksurface-wayland.c)은 GSK 렌더 노드에서 계산한 영역을 `set_blur_region`으로 전달합니다. [영역 계산 구현](https://github.com/GNOME/gtk/blob/4.24.1/gsk/gskblurutils.c)은 배경 복사·붙여넣기와 블러 노드를 추적하며, 블러 반경의 내부 임계값을 사용합니다. 단순히 투명한 GTK 위젯을 추가하는 것만으로 블러가 요청되는 것은 아닙니다.
>
> Midnightway에는 현재 React `RenderArea`가 각 창에 입력/블러 대상 영역을 등록하고 있습니다. 실제 입력 영역만 GTK에 적용하며, **컴포지터 블러 효과는 아직 구현되지 않았습니다.** `MdApp.tsx`의 모니터별 `renderAreas.bar`와 `renderAreas.overlay`에서 `blur`가 켜진 항목을 이후 블러 레이어에 사용할 수 있습니다. 각 항목은 원래 사각형, X/Y 반지름, 조상 스크롤/클리핑과 뷰포트로 제한된 `clip`을 포함합니다. toolkit의 전체 화면 backdrop과 bar의 자동 숨김 감지 영역은 입력 전용입니다.
>
> 다음 구현 단계에서는 `Gtk.Snapshot`의 `push_copy`, `push_blur`, `append_paste`, `pop`과 적절한 클리핑을 사용하는 GTK 위젯/컨테이너를 검토합니다. WebKit이 해당 노드를 덮는 현재 렌더링 구조에서 실제 요청이 발생하는지, 투명 픽셀과 둥근 모서리가 올바르게 처리되는지 직접 검증해야 합니다. API가 존재한다는 것만으로 이 구성이 동작한다고 가정하지 않습니다. 프로토콜 미지원 환경에서는 기존 UI를 유지해야 합니다.
>
> 확인 시에는 실행 환경의 `pkg-config --modversion gtk4`, `hyprctl version`, `WAYLAND_DEBUG=1` 로그를 함께 확인합니다. 버전 숫자뿐 아니라 컴포지터가 실제 `ext_background_effect_manager_v1` 전역과 blur capability를 제공하는지도 확인해야 합니다. 현재 개발 환경에서는 GTK4 런타임 및 Wayland 프로토콜 요청을 검증하지 못했습니다.

---

그렇다면 `ext-background-effect-v1`을 사용하는 방향이 가장 적합합니다. Hyprland 설정 파일을 수정하거나 `hyprctl`로 레이어 규칙을 주입할 필요 없이, Midnightway 자체에서 컴포지터에 블러 영역을 요청할 수 있습니다.

특히 현재 Midnightway의 GTK4 + WebKit 구조를 유지하면서 구현할 수 있다는 점이 좋습니다.

## 1. 사용할 프로토콜

[ext-background-effect-v1 — Wayland Background Effect Protocol](https://wayland.app/protocols/ext-background-effect-v1?utm_source=chatgpt.com)

이 프로토콜은 현재 Wayland의 staging 프로토콜입니다. Hyprland 0.56 이상에서 지원합니다.&#x20;

[image](https://www.google.com/s2/favicons?domain=https://github.com\&sz=32)

GitHub+1



동작은 간단합니다.

```
Midnightway
  │
  ├─ GTK4 / WebKit
  │
  ├─ 블러 영역 지정
  │
  ▼
ext-background-effect-v1
  │
  ▼
Hyprland
  │
  └─ 지정된 영역의 배경 블러 처리
```

클라이언트는 `wl_surface`에 연결된 `ext_background_effect_surface_v1` 객체를 생성하고 다음 요청으로 블러 영역을 지정합니다.

```
ext_background_effect_surface_v1_set_blur_region(
    effect,
    region
);
```

이때 `region`은 서피스 내부 좌표를 사용하는 `wl_region`입니다.

프로토콜은 블러 영역을 정의하지만, 블러 강도와 실제 알고리즘은 컴포지터에 맡깁니다. 따라서 사용자가 Hyprland 블러 자체를 비활성화했다면 애플리케이션이 강제로 켤 수는 없습니다.&#x20;

## 2. GTK4를 이용하면 직접 Wayland 바인딩을 작성하지 않아도 됩니다

여기서 중요한 점이 있습니다.

GTK 4.24부터 `ext-background-effect-v1`에 대한 네이티브 지원이 추가되었습니다.

GTK CSS의 `backdrop-filter`를 사용하면 GTK가 내부적으로 블러 영역을 계산하고 Wayland 프로토콜 요청까지 처리합니다.&#x20;

[image](https://www.google.com/s2/favicons?domain=https://github.com\&sz=32)

GitHub+1



Midnightway의 실제 구현 파일인 [`src/components/astal/MdApp.tsx`](https://github.com/HelloWorld017/midnightway/blob/master/src/components/astal/MdApp.tsx?utm_source=chatgpt.com)에는 다음 스타일이 있습니다.

```
const transparentStyle = css`
  background: transparent;
`;
```

우선 상태 바에 블러를 적용하려면 다음 스타일을 추가할 수 있습니다.

```
const compositorBlurStyle = css`
  background: transparent;
  backdrop-filter: blur(20px);
`;
```

그리고 상태 바 `<window>`의 `cssClasses`를 변경합니다.

```
<window
  visible
  gdkmonitor={monitor}
  layer={Layer.TOP}
  anchor={WindowAnchor.LEFT | WindowAnchor.RIGHT | WindowAnchor.TOP}
  application={app}
  cssClasses={[compositorBlurStyle]}
  $={setupBarWindow}
  onRealize={updateInputRegion}
  defaultHeight={BAR_HEIGHT_MAXIMIZED}
>
```

이 스타일은 WebKit 내부에 적용하는 CSS가 아니라 GTK 창에 적용하는 CSS입니다. 따라서 브라우저 콘텐츠에만 적용되는 블러와 달리, 컴포지터 블러 요청을 발생시킬 수 있습니다.

다만 이 예시는 상태 바의 GTK 창 전체를 블러 영역으로 지정합니다. 실제 Midnightway의 상태 바 창은 최대 높이 70px로 설정되어 있으므로, 보이는 UI의 높이보다 블러 영역이 클 수 있습니다.&#x20;

[image](https://www.google.com/s2/favicons?domain=https://raw.githubusercontent.com\&sz=32)

GitHub



또한 GTK CSS의 `20px`가 Hyprland의 블러 반경을 20px로 강제하는 것은 아닙니다. 프로토콜을 통해 전달되는 것은 블러 영역이며, 강도는 Hyprland 설정에 따릅니다.

## 3. 전체 화면 오버레이는 영역을 분리해야 합니다

Midnightway의 현재 `MdApp.tsx`를 보면 두 종류의 GTK 창을 사용합니다.

| 창          | 특징           | 권장 구현            |
| ---------- | ------------ | ---------------- |
| Status Bar | 상단에 고정된 창    | GTK CSS로 블러 요청   |
| Overlay    | 모니터 전체 크기의 창 | 실제 패널 영역에만 블러 요청 |

특히 오버레이는 다음과 같이 모니터 전체에 앵커링되어 있습니다.

```
<window
  layer={Layer.OVERLAY}
  anchor={
    WindowAnchor.LEFT |
    WindowAnchor.RIGHT |
    WindowAnchor.TOP |
    WindowAnchor.BOTTOM
  }
/>
```

여기에 `backdrop-filter`를 곧바로 설정하면 모니터 전체가 흐려질 수 있습니다.

따라서 다음 구조를 권장합니다.

GTK Overlay Window

네이티브 GTK Blur Region

나머지 영역은 투명하게 유지

GTK가 표준 프로토콜로 블러 영역 전달

Hyprland Compositor

요청된 영역에만 배경 블러 적용

이를 위해 WebKit과 별도로 네이티브 GTK 위젯을 한 층 배치할 수 있습니다.

```
// 구현 구조 예시
const container = new Gtk.Overlay();
const blurLayer = new Gtk.Fixed({
  hexpand: true,
  vexpand: true,
});

container.set_child(blurLayer);
container.add_overlay(webView);

targetWindow.set_child(container);
```

여기에서 `blurLayer`에 블러용 GTK 위젯을 추가하고, 각 위젯에 `compositorBlurStyle`을 적용합니다. WebKit은 그 위에 투명한 상태로 렌더링합니다.

이미 Midnightway에는 `notificationBubblesBounds`라는 위치 정보가 있으므로, 이를 GTK 위젯의 위치와 크기에 반영하는 방식으로 시작할 수 있습니다. 컨트롤 센터·캘린더 등은 별도로 bounds를 전달해야 합니다.&#x20;

[image](https://www.google.com/s2/favicons?domain=https://raw.githubusercontent.com\&sz=32)

GitHub



이 코드는 컨테이너 구성 예시이며, 실제 적용에는 위젯의 생성·갱신·제거와 렌더링 순서 확인이 필요합니다.

## 4. 직접 프로토콜을 구현하는 것보다 GTK를 사용하는 이유

GTK 4.24 이상에서는 GTK 자체가 이미 `ext_background_effect_surface_v1` 객체를 생성할 수 있습니다.

같은 `wl_surface`에 직접 구현한 프로토콜 객체까지 중복 생성하면 `background_effect_exists` 프로토콜 오류가 발생할 수 있습니다.&#x20;

[image](https://www.google.com/s2/favicons?domain=https://wayland.app\&sz=32)

Wayland Explorer



따라서 다음처럼 설계하는 것이 좋겠습니다.

- GTK 4.24 이상 + Hyprland 0.56 이상: GTK의 `backdrop-filter` 지원을 이용합니다.
- 프로토콜 미지원: 블러 없이 기존 반투명 UI를 유지합니다.
- 세밀한 블러 영역 제어: WebKit에서 계산한 패널 영역을 GTK 위젯에 동기화합니다.

블러 기능을 구현하기 전에 실제 프로토콜 요청이 발생하는지 다음 명령으로 확인할 수도 있습니다.

```
hyprctl version
pkg-config --modversion gtk4
```

```
WAYLAND_DEBUG=1 midnightway 2> /tmp/midnightway-wayland.log

grep -E 'ext_background_effect|set_blur_region' \
  /tmp/midnightway-wayland.log
```

## 결론

제가 Midnightway에 이 기능을 구현한다면 다음 순서로 진행하겠습니다.

1. `MdApp.tsx`의 상단 바에 GTK 네이티브 `backdrop-filter`를 적용하여 프로토콜 작동을 검증합니다.
2. 전체 화면 오버레이를 `Gtk.Overlay` 기반으로 구성합니다.
3. React UI에서 패널의 위치와 크기를 GTK로 전달합니다.
4. GTK 위젯으로 정확한 블러 영역을 생성합니다.
5. 프로토콜이 없으면 블러만 비활성화되도록 처리합니다.

핵심은 Midnightway가 `hyprland.conf`를 수정하지 않고도 블러를 요청하도록 만드는 것입니다. 표준 프로토콜을 이용하면 구현을 Hyprland 전용 IPC에 결합할 필요도 없습니다.

단, 위 코드는 저장소에 적용해 실행 검증한 패치는 아니며, 특히 WebKit 위에 배치되는 GTK 블러 영역은 실제 렌더링 테스트가 필요합니다.
